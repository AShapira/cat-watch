# Cat-watch project instructions

## Development journal

The user wants an extensive, human-readable Markdown development log for an
article about this application. Maintain `docs/development-log.md` as part of
substantive development, debugging, testing, deployment, and operational work.

- Read the current status and most recent entry before continuing this project.
- Add dated entries describing the user-visible problem, decisions and reasons,
  actual changes, experiments, failures, fixes, validation, and remaining work.
  Explain why technical details matter. Write for an interested reader who was
  not present in the chat; do not dump a terminal transcript.
- Use UTC timestamps for operational events and identify the local timezone when
  relevant. Do not invent earlier timestamps. Mark reconstructed history and
  older evidence explicitly.
- Keep an up-to-date status summary at the beginning, and append dated progress
  entries. Preserve previous observations; add corrections or later outcomes
  instead of silently rewriting history.
- Separate proposed behavior, implemented code, fixture tests, native GPU tests,
  live camera observations, real model accuracy, and external delivery. A passing
  synthetic test is not evidence of cat-behavior accuracy.
- Record enough evidence to support an article: useful counts, exact model/image
  identities, source/test/document links, limitations, and reproducible commands.
  Attribute historical results to their dated records rather than implying a
  new validation run.
- Never put secrets, authenticated camera URLs, private image contents, tokens,
  or unnecessary personal details into the journal. Public-source attribution
  and private evidence paths are different things; do not publish either without
  the user's instruction.
- Update the journal at meaningful milestones and before the final response for
  a substantive task. Mention the journal link in the final response when it was
  materially updated. Routine read-only questions do not require a new entry.

This supplements the user's permission policy. It does not authorize cloud
uploads, messages, publishing, destructive actions, or starting recording without
the required camera confirmation.
